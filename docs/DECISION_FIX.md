# 决策修复与 Snake 安全层借鉴

日期：2026-09-21。基线版本：`f7d03e4`。模型权重未改变，没有执行训练。

## Snake 为什么能保持零死亡

上游 `snake/game.py` 先构造遍历棋盘的 Hamiltonian cycle，沿循环初始化蛇身。每个方向不仅要“不撞墙、不撞身体”，还要维持蛇身的循环顺序，不能越过尾部，也不能越过食物。对于符合初始化约束的局面，这使安全后继始终可用，并持续向食物推进。

`snake/policy.py` 仍调用真实 Laya，但最终执行的是安全集合中模型概率最高的方向。若模型原始首选不安全，就替换它，同时保留原概率并增加介入计数。

上游甚至有“不用模型、随机选任一允许动作，仍能吃满棋盘”的测试。因此零死亡主要由安全条件维护，而不是要求模型每次原始决策都正确。公布的 8,160 moves / zero deaths 是有限运行统计，不能直接叫作模型原始决策的 100% 胜率。

## 五子棋采用的结构

我们借鉴的是“候选约束独立于模型概率”的结构，而不是把循环路线搬到棋盘上。五子棋有对手，允许集只能表示通过当前检查，不能表示整局一定不输。

1. 对已有棋子两格邻域内的全部空点计算特征，**先检查，再截取六个候选**，避免过早截断防守点。
2. 对每个白棋候选判断黑棋是否能立即连五；只要存在可避免的即时败招，就不允许模型选择它。
3. 在黑棋无法立即获胜时，优先选择白棋能产生两个不同连五点的走法。
4. 提前检查黑棋下一手能否产生两个连五点，覆盖从活三发展成活四及复合冲四威胁。
5. 若白棋只制造一个下一手连五点，黑棋必须堵这个点；检查这个强制应手是否反而制造黑棋双杀。不能把所有冲四都误判为好棋。
6. 普通局面再应用棋形质量门槛：同一最佳战术等级中，保留评分达到最佳值 65% 的候选，避免模型在同批候选中放弃显著更强的棋形。
7. 在允许候选中执行模型最高概率；原始概率、首选、实际落点及介入原因继续公开。若所有邻域候选都有已检出的短程败招，明确报告此限制。

实现利用一个单调性质减少计算：白棋占据一个空格不会替黑棋新造出连五点或双重连五候选，因此只需对原有黑棋威胁位置在新局面中重新检查。检查不改变调用方棋盘。

这是一组短程强制威胁检查和启发式筛选，不是完整极小化极大搜索，也不证明 65% 阈值最优。进一步增强可以加入限时迭代加深搜索，并用固定对手与未见开局进行独立评测。

## 模型输入变化

旧版只给局面摘要和若干攻击/防守计数。新版给出完整的 15×15 文字棋盘、坐标约定、当前执子方、候选落子后果、可执行标志和相对棋形质量。

输入中的战术结论与评分来自程序，不能把模型读懂这些标签当作它独立发现了策略。本次真实分词测试长度为 550–577 tokens，低于该 checkpoint 的 1024 上限，并验证候选描述与最后一行棋盘均未截断。

## 回归结果

四类基础局面分别进行八种旋转/镜像，前后使用同一 checkpoint：

| 战术 | 修复前模型原始 / 实际落子 | 修复后模型原始 / 实际落子 |
| --- | --- | --- |
| 己方活三接成活四 | 3/8 · 3/8 | 8/8 · 8/8 |
| 提前阻挡对方活三 | 6/8 · 6/8 | 6/8 · 8/8 |
| 阻挡下一手连五 | 4/8 · 8/8 | 8/8 · 8/8 |
| 直接连五取胜 | 5/8 · 8/8 | 8/8 · 8/8 |
| 合计 | 18/32 · 25/32 | **30/32 · 32/32** |

模型原始选择的改善来自输入和候选处理变化，非训练。仍有 2 个原始选择需要规则纠正。测试局面用于开发回归，且包含对称版本，不能视为独立棋力测试或实战胜率。

在 M4 上本轮 32 局面的平均整步耗时约 73 ms，最高约 125 ms；包括规则、分词、同步模型调用，排除首次加载和网络/浏览器。更完整输入比旧版慢，但在交互对局中仍可即时应手。

完整测试共 23 项，其中 21 项不需要模型，2 项需要真实 GPU。除上述 32 局面外，还覆盖：故意给坏点最高概率、强制应手反杀、即时防守优先于未来攻击、棋形质量约束、独立全盘枚举核对获胜点、原始概率保留及真实 tokenizer 完整性。

## 连续对局对照

固定黑棋启发式对手、四个相同开局，分别由修复前/后的真实 Laya 控制白棋。每局最多执行 40 次 AI 落子；达到上限记为未终局，不能算和棋或胜利。

| 黑棋开局 | 修复前 | 修复后 |
| --- | --- | --- |
| H8 | 9 手，AI 负 | 31 手，AI 负 |
| G7 | 15 手，AI 负 | 81 手，未终局 |
| G8 | 47 手，AI 负 | 54 手，AI 胜 |
| H7 | 13 手，AI 负 | 81 手，未终局 |

该对手按原版确定性棋形排序选择，不是专业引擎。小样本表明连续对局中的早期崩溃有所减少，但不能据此声称接近最优棋力。目标是逐步减少明显劣手，通过更广泛的基线和限时搜索继续改进，而不是用回归集的 32/32 代替实际能力评估。
